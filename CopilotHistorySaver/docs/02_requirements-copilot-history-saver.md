# CopilotHistorySaver 要求仕様書

## 1. 文書の目的

本書は、CopilotHistorySaver の本実装に向けて、対象範囲と要求を合意するための軽量な要求仕様書である。  
実装詳細（内部クラス構成、JSON キーの完全定義、詳細ログ設計など）は設計書に委ねる。

## 2. システムの目的・背景

- VS Code 上の GitHub Copilot Chat 履歴を、ローカル環境内で参照可能な形で保存する。
- 実環境調査と最小試作により、`workspaceStorage` 配下の `chatSessions/*.jsonl` から履歴取得可能であることを確認済み。
- 本実装では、確認済みの保存構造を前提に、運用可能な読み取り・保存処理を提供する。

## 3. 対象利用者と利用環境

- 対象利用者は、個人利用を想定した開発者（リポジトリ利用者）とする。
- 対象環境は、Windows 上の VS Code + GitHub Copilot 利用環境を主対象とする。
- 実装形態は C# のコンソールアプリケーションとする。

## 4. 対象範囲

- ローカルの VS Code `workspaceStorage`、ワークスペースハッシュ配下、`chatSessions` フォルダ、または単一 `*.jsonl` を入力対象にできること。
- `chatSessions/*.jsonl` を読み取り、セッション単位の Markdown を出力すること。
- `workspace.json` が存在する場合は、ワークスペースハッシュと実フォルダの対応解決に利用すること。
- 履歴ソース（VS Code/Copilot が保持する元データ）は読み取り専用で扱うこと。

## 5. 機能要求

- 指定された入力パスから処理対象の `chatSessions/*.jsonl` を列挙できること。
- 各 JSONL を 1 行単位で解析し、セッション情報と質問・回答情報を復元できること。
- 解析対象の主要構造として、`kind:0`（スナップショット）、`kind:1`（更新）、`kind:2`（追記）を処理できること。
- 取得した情報を、セッション単位の Markdown ファイルとして出力できること。
- セッション単位で次の情報を出力できること。  
  セッション ID、タイトル、作成日時、最終更新日時、質問数、ワークスペース情報、質問本文、回答本文。
- 1 ファイルの解析失敗や一部項目欠損があっても、警告を記録して他ファイルの処理を継続できること。
- 処理結果として、対象件数・保存件数・警告件数を利用者へ通知できること。

## 6. 入力と出力

- 入力は以下のいずれかを受け付けること。  
  `workspaceStorage` ルート、ワークスペースハッシュフォルダ、`chatSessions` フォルダ、単一 `*.jsonl` ファイル。
- 出力はローカルフォルダ配下の Markdown ファイル群とする。
- 出力先フォルダは引数または設定で指定できること。
- 出力は同一セッション再処理時に更新（上書き）できること。

## 7. エラー発生時の基本方針

- 入力パス不正、対象なしなどの実行不能条件はエラー終了とする。
- 個別セッションファイルの読み取り失敗、JSON パース失敗、未知レコードは警告として扱い、処理を継続する。
- 例外発生時も可能な限り処理継続し、最終的に警告件数を報告する。

## 8. 非機能要求

- 履歴データ処理はローカル環境内で完結すること。
- 取得した履歴データを外部サービスへ送信しないこと。
- 入力元ファイルに対して更新・削除・移動を行わないこと。
- 小規模個人利用ツールとして、過剰に複雑な構成を避け、保守可能な実装規模を維持すること。

## 9. 技術上・運用上の制約

- 実装基盤は現行プロジェクトに合わせて .NET Framework 4.8 を前提とする。
- 履歴形式は VS Code / GitHub Copilot の更新で変更される可能性がある。
- 保存元でチャットセッションが削除された場合、対応する JSONL が消える可能性があり、未取得データは後追い取得できない場合がある。
- `chatSessions` 以外（例: transcripts、debug-logs 等）の扱いは本要求では必須としない。

## 10. 対象外

- VS Code/Copilot 履歴ファイルへの書き込み、更新、削除、移動。
- 履歴の常駐監視、自動バックアップ、自動同期。
- データベース保存、GUI 提供、API 連携。
- マルチ OS への汎用対応。
- 回答評価、タグ体系の正規化、分析レポート自動生成などの高度機能。

## 11. 要確認事項

- JSONL 内の項目バリエーション（`requests` 配下のキー差異、回答本文の表現差異）の網羅範囲。
- 「回答数」の定義（どのデータ単位を 1 回答とみなすか）。
- `chatSessions` と他保存領域（transcripts 等）の関係、および実運用での優先参照方針。
- 保存タイミング・更新タイミングに関する厳密な仕様（リアルタイム性、遅延有無）。
- VS Code/Copilot のバージョン差異に対する互換性維持方針。

## 12. 将来構想

- `chatSessions` 以外の関連データ（transcripts、debug-logs など）を含む補完的解析。
- 履歴削除に備えた追記型バックアップ機能。
- 検索性向上（セッション横断検索、期間抽出、簡易集計）。
- 将来的な対象環境拡張（他 OS、他エディタ構成）と運用補助機能の追加。
