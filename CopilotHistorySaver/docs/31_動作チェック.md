## 1. `chatSessions\<UUID>.jsonl`

これが、今回最も重要な**チャットセッション本体**です。

```text

```

拡張子が `.jsonl` なので、通常のJSON配列ではなく、次のように**1行ごとに独立したJSONオブジェクト**が記録される形式と考えられます。

```json
{"type":"session","...":"..."}
{"type":"request","...":"..."}
{"type":"response","...":"..."}
```

ただし、実際のキー名や1行の意味は、ファイル本文をまだ確認できていないため確定できません。

**最重要です。**

このファイルに以下が含まれている可能性があります。

* ユーザーの質問本文
* Copilotの回答
* リクエストID
* 使用エージェント
* 使用モデル
* ツール呼び出し

* セッションID

## 2. `state.json`

これは通常のチャット本文ではなく、**Copilotによるファイル編集の状態・履歴を保存するファイル**と判断できます。

内容には次のような情報があります。

```json
{
  "version": 2,
  "initialFileContents": [...],
  "timeline": {
    "checkpoints": [...],
    "fileBaselines": [...],
    "operations": [...],
    "recentSnapshot": {...}
  }
}
```

### 主な項目

#### `version`

```json
"version": 2
```

この状態ファイルの内部フォーマットバージョンと考えられます。

VS CodeやCopilotのバージョンではなく、**保存データ構造のバージョン**である可能性が高いです。

#### `initialFileContents`

```json
"initialFileContents": [
  [
    "file:///d%3A/git/Repository3/CopilotHistorySaver/docs/CopilotHistorySaver_concept2.md",
    "da39a3e"
  ]
]
```

編集対象となったファイルと、初期状態を識別するハッシュらしき値が記録されています。

この例では、対象ファイルが以下であることが分かります。

```text
D:\git\Repository3\CopilotHistorySaver\docs\
CopilotHistorySaver_concept2.md
```

#### `timeline.checkpoints`

Copilotによる編集作業の節目を記録しています。

例として、次のような種類があります。

* `Initial State`
* `Request <requestId>`
* `Request <requestId> - Stop <undoStopId>`

つまり、Copilotの各要求・編集処理ごとに、**復元やUndoのためのチェックポイント**を管理していると考えられます。

#### `requestId`

```text
request_89045ac8-d90e-477c-9dc3-7d8f3cfccedc
request_c92d1b77-ef09-4c07-a6ef-143749b488d5
```

各Copilotリクエストを識別するIDです。

これは非常に重要で、JSONL側にも同じ `requestId` が存在すれば、

```text
チャット上の質問
    ↓ requestId
ファイル編集操作
```

という関連付けができる可能性があります。

#### `operations`

実際にCopilotが行った編集内容です。

今回のファイルでは、少なくとも次のような構造が確認できます。

```json
{
  "type": "textEdit",
  "uri": {...},
  "requestId": "...",
  "epoch": 5,
  "edits": [
    {
      "text": "...",
      "range": {...}
    }
  ]
}
```

ここには、Copilotがファイルへ書き込んだ文章がほぼそのまま記録されています。

したがって、`state.json` からは、

* どのファイルを編集したか
* どの要求による編集か
* 何を書き込んだか
* どの範囲を置換したか
* 編集の順序

を取得できる可能性があります。

#### `recentSnapshot`

最近編集されたファイルの状態を保持しています。

内容には次の情報があります。

* 対象ファイルURI
* `languageId`
* 変更前後のハッシュ
* スナップショットURI
* `requestId`
* `agentId`
* `modelId`
* `modeId`

今回のデータでは、次のような値が確認されています。

```text
agentId : github.copilot.editsAgent
modelId : copilot/auto
modeId  : agent
```

つまり、この編集が**CopilotのAgentモードによるもの**であることを識別できます。

### このファイルの位置付け

`state.json` はチャット履歴そのものというより、

> チャットによって実行されたファイル編集を、Undo・復元・差分管理するための履歴

と考えるのが自然です。

CopilotHistorySaverでは、必須の読み取り対象ではありませんが、将来的に次のような解析を行うなら非常に有用です。

```text
質問
↓
Copilot回答
↓
ツール実行
↓
実際のファイル変更
```

```text

│    ├─ Copilotの回答

│    └─ モデル・エージェント情報

│    ├─ requestId
│    ├─ 編集対象ファイル
│    ├─ 実際の編集内容

│
└─ models.json
```

特に重要な関連キーは、次の2つです。

```text
sessionId
requestId
```

予想される関連構造は以下です。

```text
chatSessions/<sessionId>.jsonl

    ├─ requestId B ──→ state.json の編集操作B
    └─ modelId     ──→ models.json のモデル定義
```

### パターンB：別ファイルにセッション一覧がある

```text
セッション一覧・インデックス
    ├─ sessionId
    ├─ title
    ├─ lastModified
    └─ workspace情報

chatSessions\<sessionId>.jsonl
    └─ 質問・回答の実体
```

今回のZIP内に、タイトルを管理する別のJSONやSQLiteデータがあれば、そちらにある可能性もあります。

## 日時の確認方法

正解日時は日本時間で次のとおりです。

```text
2026/08/02 13:58 JST
```

UTCへ直すと次になります。

```text
2026/08/02 04:58 UTC
```

JSONL内で以下に近い値を探すと、日時フィールドを特定できます。

```text
2026-08-02T04:58
2026-08-02T13:58
1785646680000 前後
```

秒数には多少のずれがあり得ます。

PowerShellでは、Unixミリ秒らしき値を次のように変換できます。

```powershell
[DateTimeOffset]::FromUnixTimeMilliseconds(1785646680000).ToLocalTime()
```

実際の値が秒単位なら、こちらです。

```powershell
[DateTimeOffset]::FromUnixTimeSeconds(1785646680).ToLocalTime()
```


JSONL各行のトップレベルキーを調べるには、次のスクリプトが有効です。

```powershell
$path = "C:\Users\intru\AppData\Roaming\Code\User\workspaceStorage\777123967f1588172686ce203d720947\chatSessions\55e83327-2f51-42fc-9c74-17c4d7120430.jsonl"

$lineNumber = 0

Get-Content -Path $path -Encoding UTF8 | ForEach-Object {
    $lineNumber++

    try {
        $obj = $_ | ConvertFrom-Json
        $keys = $obj.PSObject.Properties.Name -join ", "

        [PSCustomObject]@{
            Line = $lineNumber
            Keys = $keys
        }
    }
    catch {
        [PSCustomObject]@{
            Line = $lineNumber
            Keys = "<JSON解析失敗>"
        }
    }
} | Format-Table -AutoSize
```

## 現段階の判定

構想書の調査事項については、次のように更新できます。

### 確認済み

* Copilot Chat履歴は、対象環境では `workspaceStorage\<workspace-hash>\chatSessions` に存在する。
* セッションは `.jsonl` ファイルとして保存されている。
* ユーザーの質問本文はJSONLから検索できる。
* ワークスペースごとに異なるハッシュフォルダへ分けられている。

### 可能性が高い

* 回答本文も同じJSONLから取得できる。
* JSONL内のユーザー要求レコード数から質問数を算出できる。
* セッションIDとJSONLファイル名が対応している。

### 引き続き確認が必要

* タイトルがJSONL内にあるか、別のインデックスにあるか。
* 作成日時のキー名と保存形式。
* 質問と回答を結び付けるID。
* 質問1件に複数回答や再生成がある場合の数え方。
* 中断・失敗・キャンセルされた回答の扱い。
* Ask、Plan、Agentなどモード別のデータ構造差。
* セッション削除後もJSONLが残るか。

なお、現時点ではこちらから対象JSONL本文自体を直接参照できていないため、具体的なキー名までは確定できません。`jsonl` を `.txt` にコピーしてアップロードすると、各レコードの意味、質問・回答・タイトル・日時・質問数の抽出規則まで確定できます。
