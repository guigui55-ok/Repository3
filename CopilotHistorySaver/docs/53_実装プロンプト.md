## 今回の目的

Windows 11 上の VS Code `workspaceStorage` に保存されている GitHub Copilot Chat の履歴を読み取り、対象ワークスペースごとに整理してローカルファイルへ保存できる、実用可能な C#コンソールアプリを実装します。

## 基本要件

次の要件を本実装の基準としてください。

1. 既存の C# / .NET Framework / Console アプリの構成を維持する。
2. 既存の最小試作を土台とし、利用可能な処理は再利用する。
3. `workspaceStorage` 配下を読み取り専用で処理する。
4. `workspace.json` など、動作確認で有効性を確認できた情報から対象ワークスペースを識別する。
5. 各ワークスペースの `chatSessions` 配下にある `*.jsonl` を検出する。
6. JSONLを安全に解析し、少なくとも次の情報を取得する。

   * ワークスペースの識別情報
   * セッションID
   * チャットタイトル
   * ユーザーの質問本文
   * 作成日時・更新日時
   * 質問数またはメッセージ数
7. 回答本文など、最小試作で安定して取得できることを確認済みの情報は、取得対象へ含める。
8. タグなど、取得方法が確定していない情報は推測で生成しない。
9. 対象とするワークスペースまたはフォルダを指定できるようにする。
10. 取得結果をローカルファイルへ保存する。
11. 出力形式、ファイル単位、既存ファイルの更新方法は、既存資料や最小試作に方針があればそれを優先する。
12. 同じ履歴を繰り返し実行した場合に、不必要な重複が発生しないようにする。
13. 一部のファイルや行を読み取れない場合でも、可能な範囲で他の処理を継続する。
14. エラー発生時は、対象ファイルと原因を確認できるようにする。
15. VS CodeおよびCopilotの管理ファイルを作成・更新・削除しない。
16. 履歴データを外部サービスへ送信しない。

## 設計・実装方針

* 実際の動作確認データと最小試作の解析結果を根拠に実装してください。
* 特定のセッションID、ワークスペースID、ユーザー固有パスに依存するハードコードは行わないでください。
* 入出力パスなど、環境によって変わる値は設定またはコマンドライン引数で変更可能にしてください。
* JSONLの形式差異、欠損項目、未知のレコードを考慮してください。
* VS CodeやCopilotの更新による形式変更の影響を、解析処理の局所的な修正で対応できる構成にしてください。
* 不要な高度化や過剰な抽象化は避け、現時点で必要な責務に絞ってください。
* 外部パッケージの追加は最小限とし、追加する場合は理由と互換性を確認してください。
* 実際のCopilot履歴や機密情報を、テストデータとしてGitへ登録しないでください。
* テストデータが必要な場合は、構造を維持した匿名・最小データを使用してください。
* 無関係な既存コードやドキュメントは変更しないでください。

## コード構成

ユーザーがコードリーディングと保守をしやすい構成にしてください。

* 処理全体を俯瞰できる「目次」のようなメソッドを中心に構成する。
* 中心となるメソッドから、処理の流れを順番に追えるようにする。
* メソッドが長くなった場合は、同じ目的を持つ処理単位で分割する。
* 1つのメソッドやクラスに、異なる責務を詰め込まない。
* クラスやメソッドを細かく分割しすぎて、全体の流れが分かりにくくならないようにする。
* 既存のコーディングルールがある場合は、そちらを優先する。

## テスト

実装に対応したテストを追加し、少なくとも次を確認してください。

* 正常なJSONLから必要な情報を取得できる。
* 複数ワークスペース、複数セッションを処理できる。
* 質問が複数存在するセッションを処理できる。
* 削除済みセッションや残存ファイルを、確認済みの仕様どおり扱える。
* 空ファイル、不正なJSONL、未知のレコード、欠損項目があっても処理全体が停止しない。
* 対象外ワークスペースを除外できる。

* 出力先が存在しない場合や書き込めない場合に、適切なエラーとなる。
* 読み取り元のファイルを変更していない。

可能であれば、既存の動作確認データでも実行し、記録済みのタイトル・質問本文・セッション数などと照合してください。
