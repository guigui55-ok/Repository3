# VS Code / GitHub Copilot チャット履歴調査計画書

## 1. 調査目的

本調査の目的は、VS Code 上で利用する GitHub Copilot のチャット履歴が、ローカル環境上で取得可能かどうかを確認することにある。特に、履歴がどこに保存されるか、どの形式で残るか、取得に必要な情報が存在するかを確認する。

調査の主眼は、実装そのものではなく、後続の最小試作に向けた前提確認とする。

## 2. 調査項目

本調査では、以下の項目を確認する。

- Copilot Chat の履歴がどこに保存されるか
- 保存先候補として .vscode、workspaceStorage、Users 配下のデータが実在するか
- 保存形式が JSON、テキスト、SQLite、ログ、その他のいずれかであるか
- 質問本文・タイトル・作成日時・タグ・セッション情報などのメタ情報が残っているか
- ワークスペースと履歴データの対応関係があるか
- 公式 API や公開仕様があるか
- 読み取り専用で利用可能か

## 3. 確認する保存場所

以下の保存場所を優先して確認する。

- VS Code の workspaceStorage 配下
- 各ワークスペース配下の .vscode 関連ディレクトリ
- Windows の Users 配下にある VS Code / Copilot 関連データ
- 必要に応じてキャッシュやログ領域

確認の際は、これらが「実際に存在するか」「履歴データと関連するか」を重点的に確認する。

## 4. 確認するファイル形式

履歴データの保存形式は、以下の候補を確認対象とする。

- JSON
- テキスト
- SQLite
- ログファイル
- その他の構造化データ

実際にどの形式で保存されているかを確認し、内容の読み取りが可能かどうかを評価する。

## 5. 実験手順

1. 既知の短い Copilot Chat を 1 件実行する。
2. 実行したワークスペース名と時刻を記録する。
3. 候補ディレクトリを確認し、関連ファイルを一覧化する。
4. 新規作成または更新されたファイルを特定する。
5. ファイル内容や構造を確認し、履歴として利用できる情報があるかを確認する。
6. 取得可能な情報を整理し、次の工程である最小試作に繋げる。

## 6. 取得可否の判定基準

取得可否は、以下の基準で判定する。

- 保存先が特定できること
- 履歴内容がファイルまたは構造化データとして残っていること
- 主要なメタ情報を取得できること
- 読み取り専用で実行可能であること
- 利用規約・機密管理上の制約に抵触しないこと

判定は、以下の 3 段階で行う。

- 取得可能: 主要な情報を十分に取得できる
- 条件付きで取得可能: 取得できるが、形式や保存場所に依存する
- 取得不可: 取得元が不明、または読み取り方法が確立できない

## 7. セキュリティ上の注意

本調査はローカル環境の履歴を確認するため、以下の点に十分注意する。

- ローカル環境内のデータのみを対象とする
- 取得対象ファイルを改変しない
- 機密情報や個人情報を含む可能性があるため慎重に扱う
- 取得結果を外部サービスへ送信しない
- 出力内容に機密情報が残らないようにする

## 8. 調査結果の記録方法

調査結果は、以下の方法で記録する。

- 調査日時
- 対象環境情報
- 確認した保存先
- 確認したファイル形式
- 取得できた内容
- 取得できなかった内容
- 今後のアクション

記録は、後続の要件定義・最小試作・実装にそのまま反映できるように整理する。

## 9. 調査の優先順位

調査は、以下の順で進める。

1. まず履歴の保存場所を確認する
2. 次に保存形式とファイル構造を確認する
3. その後、質問本文・タイトル・作成日時などの主要項目が取得可能かを確認する
4. 最後に、読み取りの妥当性とセキュリティ観点を評価する

## 10. 構想書との整合性に関する補足

構想書では「回答も収集したい」とあるが、現時点では必須ではないため、調査計画では主に質問内容・保存場所・形式の確認を優先する。また、保存先に関する記述は、現時点では仮説として扱い、実際の確認結果で確定させる。

さらに、構想書内の長期的な AI 活用構想は重要である一方、当面の調査では「履歴の保存場所と取得方法」を確認することに集中する。
