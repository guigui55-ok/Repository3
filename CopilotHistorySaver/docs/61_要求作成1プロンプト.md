# CopilotHistorySaver 要求仕様書作成プロンプト

CopilotHistorySaver について、本実装に向けた簡単な要求仕様書を作成してください。

## 現在の状況

- Copilot Chat 履歴の保存場所・ファイル構成に関する実環境調査は完了しています。
- 取得可能性を確認するための最小試作も完了しており、これから本実装へ進む段階です。
- 構想書などに「次に最小試作を行う」といった古い記述が残っている場合は、現在の進捗を優先してください。

## 参照資料

最初にリポジトリ全体を確認し、少なくとも次の資料と現在のソースコードを参照してください。

- `docs/CopilotHistorySaver_concept2.md`
- `docs/01_research-vscode-copilot-history-investigation-plan.md`
- `docs/31_動作チェック.md`
- `docs/33_動作チェック2.md`
- `docs/34_動作チェック3.md`
- 履歴ファイルの解析結果を記録した資料
- 最小試作として作成したソースコードおよび関連資料

ファイル名や配置が異なる場合は、同等の資料をリポジトリ内から探して参照してください。

情報の優先順位は、原則として次の順とします。

1. 現在のソースコードと実環境で確認済みの結果
2. 動作確認・解析結果を記録した資料
3. 調査計画書
4. 構想書

資料間で内容が矛盾する場合は、推測で統合せず、より新しく実証済みの情報を採用してください。判断できない事項は「要確認事項」として残してください。

## 作成する文書

出力先：`docs/02_requirements-copilot-history-saver.md`

文書名：`CopilotHistorySaver 要求仕様書`

この文書は、本実装の対象範囲と要求について、開発者と依頼者が認識を合わせるための軽量な要求仕様書とします。詳細設計書のように細かな内部実装まで記載する必要はありません。

次の章立てを基本として、簡潔に整理してください。

1. 文書の目的
2. システムの目的・背景
3. 対象利用者と利用環境
4. 対象範囲
5. 機能要求
6. 入力と出力
7. エラー発生時の基本方針
8. 非機能要求
9. 技術上・運用上の制約
10. 対象外
11. 要確認事項
12. 将来構想

## 記載方針

- 調査や最小試作で確認済みの事実を、正式な要求へ整理してください。
- 「確定事項」「要確認事項」「将来構想」を混在させないでください。
- 本実装で必要な要求と、将来追加する可能性がある機能を明確に分けてください。
- 保存元の Copilot Chat 履歴は読み取り専用で扱い、変更・削除しないことを要求として明記してください。
- 一部の履歴ファイルやレコードを解析できない場合でも、警告を記録し、可能な範囲で処理を継続する方針を反映してください。
- ローカル環境内で処理を完結し、取得した履歴を外部サービスへ送信しない方針を反映してください。
- VS Code や GitHub Copilot の更新によって保存形式が変わる可能性を、制約または要確認事項として整理してください。
- パス、JSONL のレコード構造、クラス構成、メソッド構成、画面項目、DB定義、詳細なログ形式などは、要求の理解に不可欠なものを除き、設計書へ委ねてください。
- 構想書の文章をそのまま転載せず、重複を除いて要求仕様書として再構成してください。
- 未確認の機能や仕様を推測で追加しないでください。
- 各要求は、可能な範囲で「～する」「～できること」の形で明確に記載してください。
- 小規模な個人利用ツールとして、過剰に大規模・複雑な要求にしないでください。

## 作業上の制約

- 今回は要求仕様書の作成だけを行ってください。
- ソースコード、構想書、調査資料、その他の既存ファイルは変更しないでください。
- 不明点があっても作業を止めず、文書内の「要確認事項」に整理してください。
- 作成後、参照した主な資料、確定事項として採用した内容、要確認事項の概要をチャットで簡潔に報告してください。
