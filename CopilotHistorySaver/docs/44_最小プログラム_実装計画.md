# 読み取り専用最小プローブ 実装計画

## 1. 今回の目的

- VS Code の `workspaceStorage` または `chatSessions` を入力として受け取り、`chatSessions` 配下の JSONL を読み取り専用で列挙する。
- 実データから確認できた項目だけを抽出し、コンソール表示できることを確認する。
- 欠損項目や構造差異があっても処理継続できる最小構成とする。

## 2. 読み取り対象となるフォルダとファイル

- 入力対象
	- `workspaceStorage` ルート
	- `chatSessions` 直指定フォルダ
- 読み取り対象
	- 各ワークスペース配下の `chatSessions/*.jsonl`
	- 各ワークスペース配下の `workspace.json`（存在時のみ）
- 根拠資料
	- `docs/CopilotHistorySaver_concept2.md`
	- `docs/01_research-vscode-copilot-history-investigation-plan.md`
	- `docs/31_動作チェック.md`
	- `docs/32_動作チェックログ.md`
	- `docs/33_動作チェック2.md`
	- `docs/34_動作チェック3.md`

## 3. 実データから確認できた JSONL 構造

- `chatSessions/*.jsonl`
	- `kind` と `v` を持つ行がある。
	- `kind:0` 行で `v` 内に `sessionId`, `creationDate`, `customTitle`, `requests` を確認。
	- `kind:1` / `kind:2` の差分更新行（`k` パスと `v` 値）を複数確認。
- `workspace.json`
	- `folder` があり、workspace hash と実フォルダ対応を確認可能。
- 補足
	- `transcripts` と `debug-logs` 形式も存在する。
	- ただし今回の最小実装対象は `chatSessions` を主対象とする。

## 4. 取得する項目

- セッションファイル名
- セッション ID（`sessionId`）
- セッションタイトル（`customTitle`）
- セッション作成日時（`creationDate`）
- 質問件数（`requests` 配列件数）
- 各 request の `requestId`
- 各 request の `timestamp`
- `response`（存在時の取得可能範囲）

### 未確認事項

- タグ（tag）の存在と取得方法
- 回答数の厳密定義（`response` のどの粒度を 1 件とするか）
- requests 配下の本文キー名の全バリエーション

- 追加候補（最小分割する場合）

	- `sample_project/CopilotHistorySaveSample/ConsoleReporter.cs`

## 6. クラスとメソッドの最小構成

- `Program`
	- `Main(string[] args)`
		- 入力受け取り
		- 実行フロー制御
		- 終了コード返却
- `HistoryScanner`
	- `ResolveTarget(string inputPath)`
		- `workspaceStorage` / `chatSessions` 判定
	- `EnumerateSessionFiles(string path, TargetKind kind)`
		- 解析対象 JSONL 列挙
- `SessionParser`
	- `ParseSessionFile(string jsonlPath)`
		- 1 行ずつ読み取り
		- `kind` 別取り込み
	- `TryExtractSummary(...)`
		- 表示用要約へ変換
- `ConsoleReporter`
	- `PrintSessionSummary(...)`
	- `PrintWarning(...)`

## 7. エラー時の扱い

- 1 ファイル単位で失敗しても全体停止しない。
- JSON パース失敗、キー欠落、アクセス失敗は警告表示して次ファイルへ継続する。
- 入力パス不正や対象 0 件は非 0 終了コードで終了する。
- 元ファイルへの書き込み・更新・削除・移動は行わない。

## 8. 実行方法（実装後）

- 既存プロジェクトをビルドして実行する。
- 実行引数に `workspaceStorage` または `chatSessions` のパスを指定する。
- セッション要約をコンソールに表示する。

## 9. 動作確認方法（実装後）

- `workspaceStorage` 指定で複数 hash 配下を列挙できることを確認。
- `chatSessions` 直指定で当該フォルダのみ列挙できることを確認。
- 既知識別文字列の取得確認
	- `TEST_HISTORY_20260802_001`
	- `TEST_HISTORY_20260802_002`
	- `TEST_HISTORY_20260802_011`
	- `TEST_HISTORY_20260802_012`
- 不正パス・破損行で警告継続できることを確認。
- 削除済みセッションは現存ファイルのみ対象になることを確認。
