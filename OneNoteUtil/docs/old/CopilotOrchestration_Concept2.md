# 背景
ユーザー（私）はソフトウェアエンジニアで、をソフトウェアの開発をしている。
参画している案件では、1つの大規模なクライアント・サーバーシステム（複数Editionあり）の機能追加・改修を行っている。
作業の特徴として、小さな依頼（1機能の追加・回収）に一人の担当者をアサインし、その中で「事前調査・検討→概略見積→詳細調査→要求仕様→仕様書反映→詳細設計書→試験仕様書（テスト設計・項目作成）→試験実施」というフェーズを行う。

業務では GitHub Copilot(VsCode環境) を使用しており、作業の効率化を求められている。
（個人的にも学習したい。別件で自身でも小さな個人案件を対応したいと考えているため）
最終的に、Copilotによるオーケストレーションで、作業すべて～9割くらいの作業を自動化したいと考えている。
・9割くらいとは、調査実施/方針の検討/各種ファイルの作成をCopilotがすべて行い、そのレビューもCopilotが主に行う。（レビューはユーザーも行う）。そして、レビュー後の最終決定はユーザーが行うことを指す。
そして、作業すべてとは、上記すべての事を指す。
・最終目標としてはすべての作業の自動化だが、一旦9割の自動化をまず最初の目標とする。
・自動化したい工程は、本書の`# 対応したいフェーズ・作成する成果物`のすべてが対象。

全体の大まかな構想として、以下の事を考えている。
[全体の大まかな構想]
1. プロンプトを手動打ち込みで各作業を行う
    →よく使うプロンプトや、効率的なプロンプトを学習

6. 本手順1～6の繰り返し。でどんどん効率化していく
* レビューはユーザーによる目視をメインに行うが、最終的にCopilotに移管・もしくはCopilotで半自動化する予定。

まず個人で簡易的なツールを複数作りたいので、このツール作成とともにオーケストレーションも完成させていきたい。

## prompt → agent → skill への昇格条件
まずは、ユーザーがプロンプトを手動入力して、その中で定型化できそうなもの（他の作業で流用できそう）、同様の内容を複数回入力しているもの[3回以上]、などをユーザーが判断して、プロンプト化する。
Copilot のほうでも、この観点で有効なprompt,agent,skillを作成できるかを少し検討して、提案してもらえるとよいと考えている。
昇格の可否は、回数だけでなく以下の観点でも判断する。

* 再利用頻度: 同じ目的で複数回使っているか、今後も継続的に使う見込みがあるか。
* 入力の安定性: 必要な前提や入力項目が毎回ほぼ同じか。
* 出力の安定性: 期待する成果物の形式や粒度が毎回ほぼ同じか。
* 手順の固定度: 実行手順を明文化しやすく、毎回の判断が少ないか。
* 独立性: 他の作業に強く依存せず、単独の役割として切り出せるか。
* 失敗時の修正容易性: 失敗しても原因が追いやすく、テンプレート化しやすいか。
* チェイン適性: 前後工程と入出力でつなげやすいか。

目安としては、次のように切り分ける。

* prompt に留める: 1回限り、内容が流動的、毎回大きく書き換える。
* agent に昇格する: 同種作業が複数回あり、会話の流れは必要だが、手順と出力はかなり固定できる。
* skill に昇格する: 手順がほぼ固定で、判断基準も明文化でき、複数案件で再利用できる。

各段階の目安を、入力・期待出力・昇格条件・除外条件で整理すると次の通り。

* prompt
    * 入力: その場限りの依頼内容、前提、制約、対象ファイル。
    * 期待出力: 1回の作業に直接使える回答、下書き、確認観点。
    * 昇格条件: 同じ目的で複数回使い、入力の形がほぼ固定化してきたとき。
    * 除外条件: 毎回大きく内容が変わる、判断余地が大きい、会話の往復が少ないと成立しない。

* agent
    * 入力: ある程度定型化した依頼、必要な前提情報、途中確認を含む作業指示。
    * 期待出力: 会話を挟みながら進める中間成果物、整理済み案、次工程に渡せる成果物。
    * 昇格条件: 会話の流れは必要だが、手順と出力の型を固定しやすく、繰り返し使う見込みがあるとき。
    * 除外条件: 完全自動の手順に落とせる、または毎回の判断が大きく変わって定型化しにくい。

* skill
    * 入力: 目的と前提が明確で、実行手順に必要な情報が揃っている作業指示。
    * 期待出力: 固定した手順に従って作成される成果物、チェック結果、再利用可能な実行手順。
    * 昇格条件: 手順と判断基準を明文化でき、複数案件でも同じ流れで再利用できるとき。
    * 除外条件: 入力や判断が都度大きく変わる、例外対応が多い、汎用手順として切り出しにくい。
