# Github Copilot オーケストレーション構築 構想書

この文書は、サンプルプログラムの実装前に、構想内容を整理し直したものである。  
実装方針には踏み込まず、現時点での目的・前提・要望・未解決事項を明確にすることを目的とする。

# 背景
ユーザー（私）はソフトウェアエンジニアで、を府とウェアの開発をしている。
参画している案件では、1つの大規模なクライアント・サーバーシステム（複数Editionあり）の機能追加・回収を行っている。
作業の特徴として、小さな依頼（1機能の追加・回収）に一人の担当者をアサインし、その中で「事前調査・検討→概略見積→詳細調査→要求仕様→仕様書反映→詳細設計書→試験仕様書（テスト設計・項目作成）→試験実施」というフェーズを行う。

業務では GitHub Copilot(VsCode環境) を使用しており、作業の効率化を求められている。
（個人的にも学習したい。別件で自身でも小さな個人案件を対応したいと考えているため）
最終的に、Copilotによるオーケストレーションで、作業すべて～9割くらいの作業を自動化したいと考えている。

全体の大まかな構想として、以下の事を考えている。
[全体の大まかな構想]
1. プロンプトを手動打ち込みで各作業を行う
    →よく使うプロンプトや、効率的なプロンプトを学習
2. よく使う手動プロンプトを、Copilotの prompt.md化する。
3. よく使う prompt.md を Copilotの agent.md化する。
4. 上記で手順が固まったものがあれば Copilotの skill.md化をする。
5. 上記の機能をなるべく連結（チェイン）させる。
6. 上記1-6の繰り返し。でどんどん効率化していく
* レビューはユーザーによる目視をメインに行うが、最終的にCopilotに移管・もしくはCopilotで半自動化する予定。

まず個人で簡易的なツールを複数作りたいので、このツール作成とともにオーケストレーションも完成させていきたい。

# 対応したいフェーズ・作成する成果物

* 設計書（基本・詳細まとめる）
* 試験仕様書（テスト設計・項目）
* その他（仕様手順書・マニュアルなど）

# 現状
今のフェーズとしては、全体の大まかな構想の1-2の段階。
手動プロンプトによって以下のフェーズの作業を少し行った。

* 手動で記載した基本構想を整理
* 基本構想書から、要求、実装プランを作成
* 実装プランから実装を行った

# 課題
* 前回実装時に実装にcreditを多く消費した（500くらい）
    - デフォルトのPlanエージェントは使用しない（コンテキストを多く消費するため）
        →基本は Lite-Ask、Lite-Editを使用する。
* 実装で想定と異なるソース・ファイル構成となった。
    - ソースファイル・構成などを指定する。
